# Bu'kuma — Deployment Guide

Bu'kuma is the shop management system for **M.Fenfaquee Enterprise**.

| Part | Folder | Hosted on | Address (example) |
|---|---|---|---|
| Frontend (React PWA) | `mbefoe/` | **Netlify** | `https://bukuma.netlify.app` |
| Backend (FastAPI) | `mbeyen/` | **Render** | `https://bukuma-api.onrender.com` |
| Database (PostgreSQL) | — | **Supabase** (already set up) | — |

The order matters, because each service needs the other's address:

1. Push the code to GitHub.
2. Deploy the **backend** on Render and copy its address.
3. Deploy the **frontend** on Netlify, giving it the backend address.
4. Tell Render the frontend address (CORS).
5. Install the app on your phone.

---

## 0. Before you start

- [ ] **Change your Supabase database password.** It was shared in a chat, so treat it as exposed. Go to Supabase → Project Settings → Database → **Reset database password**. Use letters and numbers only; `$ @ # / ?` break connection URLs.
- [ ] Update `DATABASE_URL` in `mbeyen/.env` with the new password, and check the app still works locally.
- [ ] Have accounts on **github.com**, **render.com** and **netlify.com**. Signing in to Render and Netlify *with GitHub* is easiest.

## 1. Push the code to GitHub

### What gets pushed (and what doesn't)

The root `.gitignore` keeps out:

| Never pushed | Why |
|---|---|
| `mbeyen/.env`, any `.env` | Contains your database password and secret key |
| `mbeyen/mshop/` | Python virtual environment (huge, machine-specific) |
| `mbefoe/node_modules/`, `mbefoe/dist/` | Installed packages / build output — rebuilt on the server |
| `__pycache__/`, `.pytest_cache/`, `*.db` | Generated files |

Everything else is pushed: **236 files**, listed in full in the [Appendix](#appendix--files-pushed-to-github).

### Commands

Open **PowerShell** (or VS Code's terminal) and run these one at a time. Replace `YOUR-USERNAME/YOUR-REPO` with your repository.

```powershell
cd "D:\New folder (2)\M.Fenfaquee Ent"

# one-time: tell Git who you are (skip if done before)
git config --global user.name  "Your Name"
git config --global user.email "you@example.com"

```

**Check the `git status` output before committing.** You must **not** see `.env` (only `.env.example`), `mshop`, or `node_modules`. If you do, stop and fix `.gitignore` first.

```powershell
git commit -m "Bu'kuma: shop management system (FastAPI backend + React PWA frontend)"
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPO.git
git push -u origin main
```

- The first push opens a browser window to sign in to GitHub. Approve it.
- **"rejected… fetch first"** means your GitHub repo already has files, e.g. a README created on the website. Run:
  ```powershell
  git pull origin main --allow-unrelated-histories --no-edit
  git push -u origin main
  ```
- **"remote origin already exists"**: `git remote set-url origin https://github.com/YOUR-USERNAME/YOUR-REPO.git`

### Pushing changes later

## 2. Backend on Render

The repo includes **`render.yaml`**, a blueprint that configures everything.

1. Go to **dashboard.render.com** → **New +** → **Blueprint**.
2. Connect GitHub if asked, then pick your repository → **Connect**.
3. Render reads `render.yaml` and shows a service called **`bukuma-api`**. It asks for two values:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Your Supabase connection string: Supabase → **Connect** → **Session pooler** URI (port **5432**), with your password filled in |
   | `CORS_ORIGINS` | For now: `http://localhost:5173`. You'll change it in step 4. |

   `SECRET_KEY` is generated by Render automatically. `PYTHON_VERSION` and `ENVIRONMENT=production` are already set.
4. Click **Apply**. The first build takes 3–5 minutes. It runs `pip install`, then on start `alembic upgrade head` (applies database migrations; safe to run every time), then starts the API.
5. When it shows **Live**, copy the address at the top, e.g. `https://bukuma-api.onrender.com`.
6. Test it: open `https://bukuma-api.onrender.com/health` in a browser. It should show `{"status":"ok"}`.

> **Free plan note:** the backend goes to sleep after 15 minutes without visits. The next request wakes it, which takes about **30–60 seconds**: the first login of the day will be slow, then it's fast. To avoid this, upgrade to Render's Starter plan, or set up a free monitor such as UptimeRobot to open `/health` every 10 minutes.

Your existing data and owner login (`mfenfaquee`) are in Supabase, so they work immediately. There's nothing to recreate.

## 3. Frontend on Netlify

The repo includes **`netlify.toml`**. It tells Netlify to build the `mbefoe` folder, serve every page correctly, and keep the app's update file (`sw.js`) uncached.

1. Go to **app.netlify.com** → **Add new site** → **Import an existing project** → **GitHub** → pick your repo.
2. Netlify fills the build settings from `netlify.toml`: base `mbefoe`, command `npm ci && npm run build`, publish `dist`. Leave them as they are.
3. Before deploying, click **Add environment variables** and add:

   | Key | Value |
   |---|---|
   | `VITE_API_URL` | `https://bukuma-api.onrender.com/api/v1`, using **your** Render address plus `/api/v1` |

4. Click **Deploy**. It takes 1–2 minutes.
5. Optional: change the site name in **Site configuration → Change site name**, e.g. to `bukuma`, which gives you `https://bukuma.netlify.app`.
6. Copy your final Netlify address.

> If you add or change `VITE_API_URL` later, it only takes effect after a new deploy: **Deploys → Trigger deploy → Deploy site**.

## 4. Connect them (CORS)

The backend only accepts requests from addresses it trusts.

1. Render → **bukuma-api** → **Environment** → edit **`CORS_ORIGINS`**:
   ```
   https://bukuma.netlify.app,http://localhost:5173
   ```
   Use your real Netlify address, with no trailing slash needed. Keeping `http://localhost:5173` lets local development keep working.
2. **Save changes**. Render restarts the service by itself.
3. Open your Netlify address and log in with `mfenfaquee` and your password.

## 5. Install on your phone (PWA)

**Android (Chrome):**
1. Open your Netlify address in **Chrome**.
2. Log in, then go to **Settings → Install the app → Install app**. Or use the **⋮** menu → **Install app** / **Add to Home screen**.
3. Bu'kuma appears on the home screen with the leopard logo and opens full-screen.

**iPhone (Safari):**
1. Open the address in **Safari**.
2. Tap **Share** (square with an arrow) → **Add to Home Screen** → **Add**.

**Updates:** after you push a change, the installed app picks it up the next time it's opened. Close and reopen it if needed.

**Offline:** the app's look opens instantly from the phone, but sales, stock and money always come live from the server, so it needs an internet connection. This is deliberate: it keeps records accurate.

## 6. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Login takes ~1 minute, then works | Render free plan was asleep (see section 2). Normal. |
| "Cannot reach the server" on Netlify | `VITE_API_URL` missing or wrong. Fix it, then **Trigger deploy**. |
| Browser console says **CORS** | `CORS_ORIGINS` on Render doesn't exactly match your Netlify address (`https://`, spelling). |
| Render deploy fails at `alembic upgrade head` | `DATABASE_URL` is wrong, or the password contains special characters. Use the Supabase **Session pooler** URI. |
| Render deploy fails at `pip install` | Check that `PYTHON_VERSION` is `3.12.9` in Render's Environment tab. |
| Netlify build fails | Open the deploy log. Usually a TypeScript error: run `npm run build` in `mbefoe` locally to see it. |
| Refreshing a page shows "Page not found" | `netlify.toml` wasn't pushed, or the redirect rule was removed. |
| Installed app shows an old version | Close it completely and reopen. In Chrome: Settings → Site settings → Clear data for the site. |
| Forgot the owner password | Locally, with `mbeyen/.env` pointing at Supabase: `.\mshop\Scripts\python.exe -c "from app.database.session import SessionLocal; from app.models import User; from app.core.security import hash_password; db=SessionLocal(); u=db.query(User).first(); u.password_hash=hash_password('NewPassword123'); db.commit()"`, then log in and change it in Settings. |

## 7. Running locally (unchanged)

```powershell
# Terminal 1 — backend
cd "D:\New folder (2)\M.Fenfaquee Ent\mbeyen"
.\mshop\Scripts\python.exe -m uvicorn app.main:app --reload --port 8010

# Terminal 2 — frontend
cd "D:\New folder (2)\M.Fenfaquee Ent\mbefoe"
npm run dev        # http://localhost:5173
```

The backend uses port **8010** because Splunk occupies 8000 on this PC. Local and online both use the **same Supabase database**, so anything you record locally also appears online.
